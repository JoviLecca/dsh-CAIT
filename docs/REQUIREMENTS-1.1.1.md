# CAIT v1.1.1 需求记录

**状态**：**已实现（2026-11-07）**。R1–R5 全部落地，24 个测试套件全绿（新增 `test-library-view`、`test-pagination`）。
**版本号**：`v1.1.1`（`package.json` + `lib/store-utils.js` 的 `CAIT_VERSION`）。`v1.1.0` 未单独发布，攒到一起由 `v1.1.1` 一次发出。
**记录时间**：2026-11-07。**基线**：`v1.1.0`（commit `bb5c403`）。

**实现要点（与下方设计的差异）**

- 库工作区做成了**顶层视图**（顶栏「文档 / 库」），不是模态框；原来的 `LibrariesModal` 已删除，库的改名/删除/挂载都在这一个页面里。
- 右侧面板的库按钮会把当前搜索词带进库页面（`libSeed`），术语页签传 `glossary`，TM 页签传 `tm` + `tmQuery`。
- 分页纯函数放在 `client/helpers.js`（`normalizePageSize` / `readPageSize` / `writePageSize` / `pageCount` / `clampPage` / `pageBounds` / `segmentNumberToIndex`），页大小存 `localStorage` 的 `cait:pageSize`。
- 服务端新增 `lib/library-view.js`（分页/搜索/语言维度 + `listTmEntries` / `listGlossaryEntries` / `exportTM` / `exportGlossary`）和 `lib/library-export.js`（TBX / CSV / JSON），`lib/tmx.js` 增加 `buildTmxForEntries`。
- `updateGlossary` / `deleteGlossary` 放宽为「任意库可改」，批量 `clearGlossary` 仍要求已挂载。
- 术语 CSV 解析支持第 5 列 `caseSensitive`，因此 CSV 现在可以完整往返。

## 二、需求

### R1 库内容可浏览、可逐条编辑

**现状痛点**：只能看到「与当前句段有关」的内容；想改一个术语必须先删再建；TM 要看到某条也得先构造查询。

**要求**

1. 能查看某个库里的**全部**条目，而不是只看当前句段相关的那些。
2. 能对单条内容直接修改：TM 的源文、译文、备注；术语的源文、译文、备注、大小写敏感。
3. 修改立即生效：右侧面板的当前句段命中、rail 的 QA 术语检查都要跟着刷新。
4. 冲突提示沿用现有错误：同库同语言对同源文重复 → `DUPLICATE_TM_ENTRY`（409），UI 用 toast 显示。
5. 服务端接口已经齐了（`updateTM` / `updateGlossary` / `deleteTM` / `deleteGlossary` / `addTM` / `addGlossary`），这一条**主要是前端工作**。

**验收**：改一条术语的译文 → 不重开文档，右侧命中 chip 与 QA 结果都变；改一条 TM 的源文撞已有条目 → 出现明确报错且原数据不变。

### R2 TM / 术语库独立页面

**要求**

1. 新增「库」页面（在 CAIT 内，与文档并列），**没有打开文档也能进**。
2. 页面结构：左侧库列表（TM / 术语分组），**右侧条目表**，**最右侧详情边栏**用于编辑选中条目（见第 6 条）。
3. 条目表支持：分页（条数由用户选，见第 5 条）、关键字筛选（源文/译文子串）、按库切换、按语言对筛选。
4. 每行可编辑、可删除；顶部可新增、导入（沿用现有 TMX / CSV 导入）、导出（见 R3）、清空库、新建/改名/删除库（沿用 1.1.0 的 `renameLibrary` / `deleteLibrary`）。
5. **分页条数可选**：提供 20 / 50 / 100 / 200 四档（默认 50），选择记 `localStorage`，库页面与 rail 分页共用同一套控件与偏好。页码、总数、上一页/下一页都显示出来。
6. **编辑走右侧边栏**：点一行在右侧边栏打开详情表单（TM：源文 / 译文 / 备注；术语：源文 / 译文 / 备注 / 大小写敏感），保存与删除都在边栏里；边栏未打开时表格只读，避免误改。窄宽度时边栏折叠成抽屉或覆盖层，不做第三版布局。
7. **右侧面板只显示与当前句段匹配的内容**：术语面板去掉「全部术语」区块，只留命中 chips + 「打开库」入口；TM 面板保持当前句段匹配，搜索框改成「在库中搜索」并给出「在库页面中查看全部」的入口。
8. **搜索范围由用户选**：库页面的搜索栏下方放一排库 chip，可选择参与搜索的库（默认「全部库」）；选了具体库就只搜这些库，切回「全部」则搜所有库。筛选与分页在范围变化时重置。搜索结果按库分组显示，命中条目要能看出属于哪个库。

**验收**：无文档时能从顶栏进入库页面；改完条目回到文档，右侧命中已是新值；选 20 条/页时列表 20 行、翻页正确；把搜索范围限定到 A 库后，B 库的条目不再出现。

### R3 库导出

**要求**

1. TM 导出：**只做 TMX 1.4**（与现有导入对称），范围默认为当前选中的库；文件名 `cait-tm-<库名>-<YYYYMMDD>.tmx`。
2. 术语导出：**三种格式**——`TBX`（术语交换标准）、`CSV`（`source,target,note,caseSensitive` 四列，与现有导入字段对齐）、`JSON`（`[{source,target,note,caseSensitive,sourceLang}]`）。导出格式用一个下拉选择，记住上次选择；文件名 `cait-glossary-<库名>-<YYYYMMDD>.<ext>`。
3. 导入能力目前只有 TMX（TM）与 CSV（术语），所以 round-trip 只对 TMX 与 CSV 强制；TBX 与 JSON 只做导出，测试断言「文件结构合法、条目数一致」，不要求导回。以后要导回 TBX/JSON 再单独加导入。
4. 导出必须**原样导回**（round-trip 测试：导出 → 清空 → 导入 → 条目数与原内容一致），作用于 TMX / CSV。
5. 下载通路复用现有导出文档的浏览器下载方式，不新造一套。

**验收**：TMX 用本插件的导入导回、条目数与备注一致；术语 CSV 导回同样一致；TBX / JSON 导出后能被 XML/JSON 解析且条目数、备注、大小写标志都对得上。

### R4 句段分页与编号跳转

**要求**

1. rail 分页：条数沿用 R2 的选择器（20 / 50 / 100 / 200，默认 50），底部显示「第 x–y 条 / 共 N 条」+ 上一页 / 下一页。
2. 编号输入框（1-based）+ 回车跳转：跳到该编号所在页并选中它。编辑区「第 n / 总数 段」旁也放一个同样的跳转入口。
3. 与现有能力组合：
   - 筛选（全部/待译/待审/已确认）或搜索变化时，页码归 1 并夹到有效范围。
   - 「确认并下一句」跨页时，页码跟着前进。
   - 「全部确认」后当前页可能变空，需要回落到有内容的页。
4. 顺带（成本很低）：加「跳到下一个未确认」按钮，与「确认并下一句」共用 `findNextUnconfirmed`（`lib/store.js:441`）。

**验收**：3000 段文档，输入 `1800` 两次动作内到达并选中；筛选为「待译」后页码不越界；连续「确认并下一句」能自动翻页。

### R5 版本与文档

1. `package.json` → `1.1.1`；`lib/store-utils.js:9` `CAIT_VERSION = '1.1.1'`；`STORE_VERSION` 不变（纯 UI/IO，无数据结构变化）。
2. `CHANGELOG.md` 增 `## [1.1.1]`；三份 README 更新库管理、导出、分页导航的说明。
3. 新增测试：库 CRUD 的编辑路径（术语）、导出 round-trip、rail 分页与跳转（纯函数层）。

- 不做跨库编辑（一次只在一个库内编辑；跨库只体现在搜索范围上）。
- 不做 TM 与术语库的在线同步/云存储。
- 不引入虚拟滚动：用户可选 20 条/页，分页已经够用。
- 不做 TBX / JSON 的**导入**（本轮只导出）。
- 不改三态模型与预翻译流程（v1.1.0 刚定稿）。

## 五、服务端缺口（这次必须新增的方法）

现有能力只够「按查询取几条匹配」，不够「浏览一个库」：

| 方法 | 用途 | 说明 |
| --- | --- | --- |
| `listTmEntries({ tmIds, query, page, pageSize, sourceLang, targetLang })` | 库页面表格、跨库搜索 | 现有 `lookupTM`（`lib/tm.js:99`）只看**已挂载**库、模糊打分、`limit ≤ 30`，不能分页浏览 |
| `listGlossaryEntries({ glossaryIds, query, page, pageSize, sourceLang })` | 同上（术语） | 目前没有任何列表接口，客户端是把 `bootstrap()` 里的全量 `glossary` 截断 200 条在用 |
| `exportTM({ tmId, format: 'tmx' })` | TM 导出 | 返回 `{ filename, mime, content }`，与 `exportDocument` 同形 |
| `exportGlossary({ glossaryId, format: 'tbx' \| 'csv' \| 'json' })` | 术语导出 | 同上；TBX 用 TBX-Basic 的最小结构（`termEntry` + `langSet` + `tig`） |

四个都是**只读**方法：进 `createHandlers` 白名单，**不要**进 `MUTATIONS`（否则响应会多带一份 `state`）。
